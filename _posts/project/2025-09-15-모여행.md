## 개요
> 가고 싶은 장소를 저장하고 의견을 나누며, 일정을 함께 편집하는 여행 계획 서비스입니다.

- 기간: 2025. 08. 11. ~ 2025. 09. 15.
- 인원: 8명
- 백엔드 기술: `Java 21` · `Spring Boot` · `MySQL` · `Redis`
- 인프라 기술: `Terraform` · `AWS ECS` · `GitHub Actions`
- 개인 기여: Redis Pub/Sub·SSE 기반 실시간 이벤트 전달, AWS 인프라 코드화 및 배포 자동화

## 주요 작업

### 실시간 변경 이벤트 전달

여행 계획을 여러 사용자가 함께 편집하므로, 한 사용자가 일정이나 장소를 바꾸면 다른 사용자에게도 알려야 했습니다. 채팅이나 커서 동기화처럼 밀리초 단위의 양방향 통신은 필요하지 않다고 보아, 데이터 수정은 REST API로 처리하고 변경 알림만 SSE로 보내는 방식으로 통신 구조를 단순화했습니다.

`SseEmitter`를 서버 메모리에서 관리했기 때문에, 서버가 여러 대일 때 다른 인스턴스에 연결된 사용자에게 이벤트를 보낼 수 없는 문제가 있었습니다. 변경 사항은 DB에 저장되고 이벤트는 화면 동기화를 위한 용도였기 때문에, 메시지 처리 보장보다 서버 간 전파에 초점을 두고 Redis Pub/Sub을 사용했습니다. 연결이 끊긴 동안 놓친 이벤트는 Redis에 일정 기간 보관해 재연결 시 다시 전송했습니다.

[실시간 이벤트 PR 보기](https://github.com/goorm-8bit/moyeohaeng-backend/pull/70){:target="_blank"}

### AWS 인프라와 배포 자동화

이전 프로젝트에서는 인프라를 다시 구성하기 어렵다는 이유로 사용하지 않는 자원을 정리하지 못해 비용이 계속 발생하는 일이 있었습니다. 사용하지 않는 자원은 정리하고 필요할 때 다시 구성할 방법을 찾다가 IaC를 알게 됐습니다. 이후 Terraform을 공부해 AWS 인프라를 코드로 구성했습니다.

![모여행 AWS 인프라 아키텍처](/assets/img/posts/project/모여행/architecture.webp)

배포할 때마다 같은 작업을 수동으로 반복하지 않도록 GitHub Actions로 Docker 이미지를 빌드해 ECR에 올리고, 새 이미지가 반영된 태스크 정의를 ECS 서비스에 배포하는 과정까지 자동화했습니다. 배포 후에는 각 EC2 인스턴스의 Grafana Alloy로 메트릭과 컨테이너 로그를 수집해 각각 Prometheus와 Loki에 저장하고 Grafana에서 확인했습니다.

[배포 자동화 PR 보기](https://github.com/goorm-8bit/moyeohaeng-backend/pull/40){:target="_blank"}
